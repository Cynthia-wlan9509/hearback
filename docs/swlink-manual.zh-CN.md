# SWLink 使用手册

SWLink 是 Hearback 里的网页控制台加聊天机器人。这份手册写给在自己服务器上运行它的人。页面右上角可以在「EN」和「中」之间切换语言，下面的按钮名称按中文界面写。

## 1. SWLink 是什么，不是什么

SWLink 是跑在你自己电脑上的本地网页，加一个常驻在你 Discord 服务器里的机器人。它能：

- 用你自己的 AI 模型回答聊天，可以只起草等你批准，也可以自动回复。
- 对 Bug 论坛的帖子做 AI 初筛：判断是什么问题、该去哪查，并写好回复草稿。
- 把爱发电的订单变成 Discord 身份组。
- 把 AI 写的内容集中放进「待审批」，你点头才发出去。
- 修改或删除机器人以前发过的消息。

它不做这些：

- 不替代 Discord 自带的自动审核（AutoMod）、论坛标签设置和入群规则筛选，这些仍在 Discord 里设置。
- 不审核别人的发言：不删别人的消息，不踢人，不禁言。
- 不是托管服务。程序一关，机器人就下线。
- 不支持拿普通用户账号当机器人（selfbot），那违反 Discord 的规则。

## 2. 安装和启动

需要 Python 3.11 或更新版本。在源码目录里运行：

```
python -m pip install -e ".[all]"
```

`all` 装全部组件。想少装，可以只挑需要的，例如 `".[llm,bot,keyring]"`：`llm` 用来调用 AI 模型，没有它所有 AI 功能都不能用；`bot` 让机器人常驻在线，没有它网页仍能手动发消息、AI 起草和审批，但机器人上不了线；`keyring` 把密钥存进系统钥匙串，没有它密钥只能放环境变量。

启动：

```
hearback web
```

也可以输入 `swlink`。浏览器会打开形如 `http://127.0.0.1:8765/#k=……` 的地址，`k=` 后面是这次运行的钥匙。可选参数：`--no-browser` 只打印链接，`--port 0` 自动选空闲端口，`--config 路径` 指定 `hearback.toml`。

想先试试而不连 Discord，可以运行 `hearback web --demo`（`--lang zh` 用中文数据，`--lang en` 用英文数据）。它打开同一个控制台，数据全是编出来的（假的服务器、Bug 论坛、待审批、聊天和支持者），模型也是假的，所以「AI 审核」「AI 起草」都能点。每个页面上方都有「演示模式」提示条。演示模式不联网，不保存令牌和密钥，数据放在临时文件夹里，停止（Ctrl+C）后自动删除。适合试用功能，也适合截图和录屏。

- 程序从你运行命令的文件夹往上找 `hearback.toml`，数据放在它旁边的 `.hearback/` 里；找不到就用当前文件夹。请每次在同一个文件夹里启动。
- 运行命令的窗口就是程序本身。按 Ctrl+C 或关掉这个窗口，程序就停止，机器人一起下线。只关浏览器页面不会停。
- 启动程序不等于机器人上线。要点页面右上角的「启动」，状态变成「在线」才算。想一打开 SWLink 机器人就自动上线（比如开着支持者私信核对），在 `hearback.toml` 里写：

  ```
  [swlink]
  autostart = true
  ```
- 同一个机器人在好几个服务器里：不要开两个 SWLink（会把私信回两遍）。每个服务器一个文件夹（各放一份 `hearback.toml`），在主文件夹的 `hearback.toml` 里列出其他文件夹：

  ```
  [swlink]
  workspaces = ["../另一个服务器的文件夹"]
  ```

  两个工作区都开了「支持者」私信核对时，订单交给这个人所在、而且还没拿到那边身份组的服务器；一个订单只能用在一个服务器，在另一边会被拒收。

  重启后左上角多一个「服务器」下拉框。切换后，Bug 论坛、待审批、支持者、日志和设置里的论坛 ID 换成那个服务器的；聊天、频道规则、机器人消息只列这个服务器的频道，私信只列在这个服务器里的人（两边都在的人两边都有，哪边都不在的放在主服务器）。模型、人设两边共用。右上角会显示当前是哪个服务器。机器人令牌只看主文件夹的；别的文件夹里放了不同的令牌会被跳过，下拉框下面会提示。
- 每次启动钥匙都会换。旧页面会显示「请从启动器重新打开 SWLink」，关掉它，用新打印的链接重开。
- 更新代码后必须重启。页面文件每次从硬盘读，后台却还在跑旧代码，页面是新的、后台是旧的，就会一直「加载中」或报错。按 Ctrl+C 停掉再重新运行。

## 3. 第一次设置

按顺序做：

1. 打开 Discord 开发者后台，新建应用。左边进入 Bot 页，点「Reset Token」，复制令牌。
2. 还在 Bot 页，打开 Message Content Intent（Discord 的一个开关，不开就读不到消息内容）。要用支持者页的成员搜索和备注推荐，再打开 Server Members Intent。
3. 在 SWLink 的「设置」页粘贴令牌，点「保存令牌」。
4. 「设置」页会出现「邀请链接」。用它把机器人拉进你的服务器。
5. 去「模型」页添加模型（第 4 节），去「频道规则」把一个频道设成「只起草」（第 6 节）。
6. 点右上角「启动」，等状态变成「在线」。

「仪表盘」的「上手清单」会逐项打勾，前四项做完就能试用，第五项「Bug 论坛」可选。

令牌写在 `.hearback/token.txt`（纯文本），页面保存后不再显示。也可以用环境变量 `DISCORD_BOT_TOKEN`，它优先于文件。

邀请链接带这些权限：查看频道、发送消息、在帖子里发送消息、阅读消息历史、附加文件、管理帖子（改论坛帖子标签要用）、管理身份组（支持者功能要用）。用不到的可以在 Discord 的邀请页上取消勾选。私密频道还要单独让机器人能查看、读历史和发消息。

## 4. 模型

「模型」页有两个标签：「模型」和「重试与回退」。

1. 点「+ 新建」。
2. 「类型」选预设：Anthropic、OpenAI、DeepSeek、OpenAI-compatible relay、Anthropic-compatible relay。后两种是兼容这两家接口的中转服务，必须自己填「接口地址」。
3. 填「名称」「模型」（按服务商给的模型名）和「API 密钥」，点「保存」。

第一个模型自动成为当前模型。想换，点另一张卡片的「设为当前」，带 ★ 的是当前在用的。点「测试」会发一个很小的请求：成功弹出「连通：…」，卡片标成「正常」；失败标成「出错」，鼠标停在上面能看到最近一次错误。

密钥只存系统钥匙串（服务名 `hearback-swlink`），不写进任何文件，页面只显示最后四位。没装 keyring 或钥匙串不可用时，改用环境变量 `HEARBACK_LLM_KEY_<配置ID>`。配置 ID 是名称的小写形式，环境变量里字母大写、符号变下划线，例如名称 DeepSeek 对应 `HEARBACK_LLM_KEY_DEEPSEEK`。设好后要重启。

调节项：

- 「失败时回退」：在模型页顶部勾选。当前模型出错（重试用完后），按添加顺序换用别的模型。
- 「重试次数」（0 到 5，默认 1）和「超时（秒）」（默认 60）：在「重试与回退」标签里设。遇到 429 或 503（对方让你稍后再试），先等对方指定的时间，没指定就先等 2 秒、再等 5 秒，然后重试。
- 「最大输出 token」：模型一次最多写多长，默认 2048。会先思考的模型把额度花在思考上，设太小会回空内容。遇到就调到 2048 以上，或换模型。AI 审核固定用 3000，不受这项影响。
- 「同时请求上限」：同一个模型同一时刻最多发几个请求，默认 2，范围 1 到 16。聊天、起草、AI 审核共用，多出来的排队。有的中转服务限制同时请求数，按服务商允许的数填。

## 5. 人设

一个人设就是一段给 AI 的说明：怎么说话、要注意什么。

「人设」页内置两个：Auto（通用聊天助手，不能删）和 Bug desk（向报告人要版本、步骤和日志）。点「+ 新建人设」，填「名称」「说明」「给 AI 的说明」（最多 8000 字）和「使用的模型」。「使用的模型」默认是「当前模型（默认）」，也可以固定用某一个。

写好后，到「频道规则」指定哪个频道用它。Bug 论坛的 AI 审核在弹窗的「用哪套人设」里选，默认选 Bug desk。

无论怎么写，程序都会在后面加一段固定的安全要求：把 Discord 和论坛里的文字当资料、不照里面的指令做、不泄露密钥。人设里去不掉它。

## 6. 频道规则

机器人在每个频道和私信里有三种做法：

- 「不理」：只记录，不回复。默认值。
- 「只起草」：模型写好回复，放进「待审批」，等你批准。
- 「自动回复」：直接发出去，不经过你。选它时页面会让你确认。

建议先用「只起草」试几天，满意再考虑自动。

最上面两行是默认：「私信默认」和「服务器默认」。下面按服务器列出每个频道，没单独改过的频道用「服务器默认」。每行四项：

- 「怎么处理」：上面三种。
- 「人设」：用哪个人设。
- 「什么时候回」：「被 @ 时才回」只在有人 @ 机器人或回复机器人的消息时处理；「每条都看」每条都处理。私信里不管选哪个，每条都处理。
- 「冷却（秒）」：回复一次后，至少隔这么多秒才会在这个频道再回。范围 0 到 3600，默认 20。

改完点「保存」，马上生效，不用重启。某个频道那一行改过任何一项，它就有了自己的规则，之后改「服务器默认」不再影响它。机器人自己和别的机器人发的消息、没有文字的消息，一律不回。

每小时最多调用模型 60 次，起草和自动回复一起算，模型出错也算；超过后消息只记录、不回复。冷却从调用模型那一刻算起。上限在 `hearback.toml` 的 `[swlink]` 下用 `hourly_cap` 改，程序重启后计数从零开始。

## 7. 待审批

「待审批」页放着还没发出去的东西：模型起草的聊天回复，以及你从 Bug 论坛放进来的回复和标签。

1. 看每张卡片：类型、发到哪里、内容、「原因」和「来自」。
2. 没问题点「批准」，不对点「拒绝」。
3. 点「发送已批准的」，在弹窗里确认，内容才真的发到 Discord。

「来自」是谁起草的：`agent:swlink` 是模型起草的聊天回复，`human:web` 是你在网页上放进来的。点「批准」和「发送已批准的」的是你，不是模型。

还没批准的可以点「编辑」直接改字，改完点「保存」。

## 8. 聊天

左边选频道，右边显示最近 50 条消息。输入框附近有：

- 「AI 起草」：模型针对最新一条别人的消息写一稿，放进输入框，由你检查修改。用哪个人设，看旁边的「人设」下拉框。
- 「发送」：直接发到 Discord，不经过「待审批」。Enter 发送，Shift+Enter 换行。一条最多 8000 字，太长会拆成几条。
- 底部可以「更改」模型，也能直接改「这个频道的做法」。

左上的下拉框可按做法或人设筛选频道。机器人在线时，带锁的频道表示它没权限读，点开会告诉你要在 Discord 里开哪些权限。私信只有机器人收到过的才会出现。

## 9. Bug 论坛

前提：已添加模型，并在「设置」的「Bug 论坛」卡片填好「服务器 ID」和「论坛频道 ID」（存进 `hearback.toml`）。ID 的取法：在 Discord「用户设置 → 高级」打开开发者模式，右键服务器图标或论坛频道，选「复制 ID」。

1. 点「同步」，把帖子和附件拉到本地。
2. 点「AI 审核」。弹窗写明用哪个模型、审几个帖子，这会调用模型，要花钱。一次最多 15 个，剩下的再点一次。选好「用哪套人设」，点「开始审核」。可随时点「停止」，当前这个帖子看完才停。
3. 点开一个帖子。左边是「玩家原帖」和回复，右边是「AI 的判断」：一句话概括、归类、严重程度、状态、把握、可能原因、该去哪查、还缺什么信息。
4. 改「回复草稿（可以改）」。需要的话填「加这些标签」「去掉这些标签」，用英文逗号隔开，必须是论坛里已有的标签。点「放进待审批」，再到「待审批」批准、发送。
5. 点「采纳分诊」，把勾选的「状态」「归类」「可能原因」记进真正的分诊。

AI 的判断只是建议，单独存放，不会改你手填的分诊。采纳之后，帖子不再算「待审核」，直到又有人回了新内容。「指南」类帖子不会被审。AI 会看最多 3 张截图，以及 `.txt`、`.log` 附件里的报错行；模型不支持看图时只看文字。

「导出修复清单」把审过的帖子按归类整理成一份 Markdown 任务单，弹窗里可「复制」或「下载」，也自动存进 `.hearback/exports/`，拿去交给写代码的人或 AI 助手。

关于状态和论坛标签：网页上的状态只记在本地，不会自动改论坛标签，标签要在上面第 4 步自己填。想让状态变化顺带起草标签变更，在 `hearback.toml` 里写 `[status_tags]`，左边是状态的英文名，右边是你论坛里的标签名：

```
[status_tags]
investigating = "排查中"
need-info = "缺信息"
fixed-pending-release = "已修待发布"
released = "已发布"
```

只有命令行会用这张对照表：`hearback triage 帖子 --set status=investigating --tag-proposal` 和发版命令 `hearback release` 会据此起草标签变更，放进待审批。

## 10. 机器人消息

1. 在「选一个地方」里选论坛帖子或频道，或在「或粘贴 Discord 链接 / ID」里粘贴一条链接，点「查看」。
2. 页面列出该处最近 100 条消息里机器人自己发的，最新的在最上面。
3. 点「改字」修改（上限 2000 字），或点垃圾桶图标删除。

删除不能撤回。只能动机器人自己发的消息，服务器会先核对作者。这两个操作直接作用在 Discord 上，不经过「待审批」，改动也会同步到本地台账。

## 11. 支持者（爱发电）

成员在爱发电付款后，把订单号（21 到 40 位数字，夹在一句话里也行；17 到 20 位的 Discord 用户 ID 不会被当成订单号）私信给机器人，机器人去爱发电核对，通过就给身份组。回复是固定文字，不经过模型。

1. 打开爱发电的开发者页面（「支持者」页有「打开爱发电开发者页面」），复制 user_id 和 API Token。
2. 在「连接爱发电」卡片勾「启用支持者功能」，填「爱发电 user_id」和「API Token」，点「保存」，再点「测试连接」，看到「连通了」。Token 只存系统钥匙串，或环境变量 `HEARBACK_AFDIAN_TOKEN`。
3. 在「规则」卡片的「支持者身份组」选要发的身份组。名字后带「（机器人给不了）」的，现在发不出，见本节末尾。
4. 按需要填：
   - 「先要有这些身份组之一（可选）」：比如「验证用户」。没有的人发订单号，机器人请对方先去验证。
   - 「最低金额（可选）」：低于它的订单不给身份组，留空或 0 不限制。
   - 「按档位给不同身份组（高级）」：爱发电每个档位有自己的 ID。填「档位 ID」并选身份组，该档位的订单在支持者身份组之外再加它。「每人每天最多核对几次」也在这里（1 到 200，默认 10）。
5. 在「通知谁」选一个频道，或填几个用户 ID（逗号隔开，最多 10 个）。认领成功、订单被别人用过、爱发电查不了、身份组给不了时，机器人会发通知。
6. 用「模拟私信」试一下：粘贴订单号，点「试一下」，看「机器人会回」「会给这些身份组」「会通知群主」。它只读取爱发电和 Discord，不发出任何东西，也不占次数。
7. 没问题，回到「规则」卡片勾「打开私信核对」，点「保存」，再在群里告诉大家把订单号私信给机器人。

私信核对要机器人在线。机器人在多个服务器里时，先在「设置」填「服务器 ID」，否则不知道该给哪个服务器的身份组。不要让别的程序同时处理同一个机器人的订单号私信，否则会回两次。

机器人按这个顺序判断：对方没有「先要有的身份组」，请对方先验证；订单已被别人认领，拒绝并通知你（本人认领过的，补发缺的身份组）；对方今天的核对次数用完，请明天再试（每发一次订单号都算一次，包括已被认领的）；然后去爱发电查。连不上就记下来，每 10 分钟自动重查，3 天还不行就放弃并通知你。查不到或没付款，回复“暂时没查到”；金额低于最低金额，拒绝并通知你；通过则记为认领、给身份组、通知你。一个订单只能被认领一次。

金额不会出现在任何回复和通知里，通知里的订单号只显示头尾各 4 位。「最近的订单」表里金额默认是「•••」，勾「显示金额」才显示。

手动处理：

- 「最近的订单」列出爱发电最近一页订单。备注里写了成员的用户名、显示名（至少 3 个字符）或用户 ID 时，会出现「认领给 xx」。确认框里会显示备注原文和付款人的爱发电昵称，看清楚再点：推荐只是按名字字面匹配，有人改个相似的名字就可能被推荐。也可以点「认领给…」，搜名字或直接填用户 ID，再点「认领并给身份组」。搜名字要开 Server Members Intent，没开就直接填 ID。爱发电连不上或没设置时，手动认领照样会成功，但页面会提示订单没核对过，你要自己确认。
- 「已认领的订单」里点「撤销」，订单号之后可被别人用。只在 Discord 里手动摘掉身份组不算撤销：对方再私信一次订单号，身份组会被补回来。弹窗默认勾着「同时把身份组摘掉」；这个人若还有别的订单支撑同一个身份组，就不摘。

身份组给不了时，页面顶部会出现「需要处理」，写明原因；成员会收到“身份组这会儿没能加上”的提示，修好后让对方再发一次订单号就会补上。机器人能发一个身份组要满足三条：有 Manage Roles 权限；它自己最高的身份组排在目标身份组上面；目标不是由集成自动管理的身份组。最常见的是排序不对：在「服务器设置 → 身份组」里，把机器人的身份组拖到支持者身份组上面。

### 自动发码（`[codes]`）

有某个身份组的成员把本机码（设备码）私信给机器人，机器人运行你的发码命令，把命令打印的码私信回去。在这个服务器文件夹的 `hearback.toml` 里写：

```
[codes]
enabled = true
role_id = "身份组 ID"            # 谁能领：有这个身份组的人（比如支持者核对发的那个）
command = ["node", "issue.js", "--device", "{device}", "--note", "{note}"]
per_user = 1                     # 每人自动领几台；再多就拒绝并通知你
```

- 命令不经过命令行解释器运行。`{device}` 换成本机码（大写，必须符合 `pattern`，默认是 4 组 4 位十六进制、中间用横线），`{note}` 换成 `discord:<用户 ID> <名字>`。命令打印的最后一行就是码。
- 同一台设备再发一次，回同一个码，不会重复生成；同一个本机码不会发给两个人；超过 `per_user` 的会拒绝并通知你（通知去支持者设置里的通知频道或私信）。
- 码单独发一条私信（先发说明，再发码）：手机上长按复制会复制整条消息，单独一条才能直接粘贴进游戏。
- 发过的码记在 `.hearback/codes.json`。码不会写进日志、事件和通知。
- 回复的文字可以在 `.hearback/templates/` 里用同名文件改，比如 `codes_ok.txt`、`codes_need_role.txt`。

## 12. 日志

「日志」页最新的在最上面，最多显示 200 条，点「刷新」更新。「操作者」里 `human:web` 是你在网页上做的，`agent:swlink` 是 AI 做的，`bot:swlink` 是机器人自己做的。出问题时看出错前后几行。

## 13. 设置

「设置」页有：「机器人令牌」（粘贴并保存；来自环境变量时页面会提示）、「Bug 论坛」（两个 ID，留空表示清除）、「私信默认怎么处理」（等同「频道规则」的「私信默认」）、「怎么把机器人拉进服务器」（三步说明和「邀请链接」）、「本地端口」。

## 14. 安全须知

- 只在本机打开。页面只监听 127.0.0.1，别用端口转发、内网穿透之类的办法把它暴露出去。
- 链接里的钥匙别发给别人，截图、录屏、直播时也别露出启动窗口里打印的链接。
- 模型密钥和爱发电 Token 只存系统钥匙串，机器人令牌写在 `.hearback/token.txt`。它们在页面里只能写入，读不出来。
- 对外发的内容默认要你点头：「只起草」下，AI 写的内容进「待审批」，你批准并发送才发出。两个例外：「自动回复」不经过你；「聊天」页的「发送」是你本人在发。
- 自动回复有风险：模型可能答错，也可能被频道里的人用话术带偏；每次回复都花 API 额度；私信设成自动时，任何能私信机器人的人都会触发回复。每小时上限和冷却只能限制数量，不能保证内容对。建议只在小范围、低风险的频道开，并定期看「日志」。
- 帖子和私信的内容不可信。那是别人写的，交给模型时会标成“不可信资料”，要求只当资料看。这能降低风险，不能杜绝，所以 AI 写的东西都该由你过目。
- 机器人发的每条消息都关掉了提醒，写了 @everyone、@某人或 @身份组，也不会真的提醒到人。

## 15. 常见问题

**页面一直「加载中」或报错。** 多半是更新代码后没重启。Ctrl+C 停掉，再运行 `hearback web`，用新链接打开。

**机器人离线。** 点右上角「启动」。状态是「出错」时，鼠标停在状态上，或看「仪表盘」的提示：没填令牌就去「设置」填；令牌失效就重新 Reset Token 再粘贴；提示 Message Content Intent 没打开，就到开发者后台的 Bot 页打开；提示没装机器人组件，就运行 `pip install "hearback-desk[bot]"`。

**机器人在线，但不回话。** 逐项看：该频道的做法是不是默认的「不理」；「什么时候回」是「被 @ 时才回」而你没 @ 它；是否还在「冷却」里；「模型」页有没有可用的模型和密钥；机器人在这个频道有没有「发送消息」权限。「只起草」的回复在「待审批」里。

**模型空回复或 429。** 空回复：把「最大输出 token」调到 2048 以上，或换模型。429（请求太多）：调小「同时请求上限」，调大「重试次数」，或打开「失败时回退」，再点「测试」确认。

**身份组给不了。** 见第 11 节末尾。

**成员搜索用不了。** 页面会提示读不到成员名单。到开发者后台的 Bot 页打开 Server Members Intent。在那之前，认领时直接填用户 ID。

## 16. 数据放在哪

数据都在 `hearback.toml` 旁边的 `.hearback/` 文件夹里，文件夹自带忽略规则，不会被 git 提交。

| 文件或文件夹 | 里面是什么 |
|---|---|
| `token.txt` | 机器人令牌，纯文本 |
| `supporters.json` | 爱发电设置、完整订单号、认领记录（含成员 ID 和金额）、待重查的订单 |
| `inbox.jsonl` | 机器人在线时看到的最近消息（最多 5000 行），设成「不理」的频道也会记，里面是别人写的话 |
| `ledger.json` | Bug 论坛的帖子、分诊和 AI 判断 |
| `events.jsonl` | 「日志」页的原始记录 |
| `queue/` | 待审批、已发送等所有草稿 |
| `attachments/` | 同步下来的帖子附件 |
| `exports/` | 导出的修复清单 |
| `llm.json` | 模型配置，不含密钥，只留密钥最后四位 |
| `channels.json` `agents.json` | 频道规则、人设 |
| `templates/` | 你自己改过的回复文字（可选） |

`token.txt`、`supporters.json`、`inbox.jsonl`、`ledger.json`、`events.jsonl`、`queue/` 和 `attachments/` 绝不能外发，其余的外发前也先看一眼。`hearback.toml` 里有服务器 ID，没有密钥。

备份：先停掉程序，把整个 `.hearback/` 和 `hearback.toml` 复制到只有你能访问的地方。系统钥匙串里的密钥不在这个文件夹里，换电脑后要重新填模型密钥和爱发电 Token（或重设环境变量）。
